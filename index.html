LUT → Spiking networks

Contents

These demos show how a trained lookup-table (LUT) network can be turned into a real spiking network (Izhikevich / SPNet) by direct construction — no retraining. The trick is latency coding: a vector is represented by the first-spike times of one population of neurons, and the constructed spiking circuit re-emits the LUT's output as the spike times of another population. Each page below runs the constructed spiking network live for an input you control and checks it reproduces the table exactly.

Demos

① Single LUT table → spiking circuit

One hyperplane LUT compiled to a spiking circuit: input spikes → detector/address bits → a 1-of-8 row-select decoder → output neurons whose latencies encode the stored row. Watch every spike propagate and verify the emergent output equals the table.

② Composing tables: summing outputs in the charge domain

Real models are a set of tables whose selected output vectors are added. Latencies don't sum — so each table deposits its output as synaptic charge onto shared output neurons, whose membranes accumulate O₁[x] + O₂[x] natively. Verified exact over 50k inputs.

③ Aggregating tables: delay-coded outputs + a listening population

A different architecture: each table stays a self-contained black box that emits its output as latency spikes (like ①). A separate population of aggregator neurons listens to all tables' output spikes and sums them via a sustained current until a readout clock — turning spike times into a true sum (not an order statistic). Verified exact over 50k inputs.

④ Scaling up: a hierarchical aggregation tree

Model ③'s single aggregator has fan-in that grows with the number of tables. Here the same sustained-current aggregator is arranged in a binary tree (4 tables → 2 → 1), so every neuron keeps fan-in 2 while depth grows only like log₂(N) — the scale-to-hundreds design. Verified exact over 50k inputs.

⑤ Live spnet inspector — latency-coded (leaky detectors, 6 forced-spike inputs)

The compact design: the toy LUT accepts real-valued x ∈ ℝ⁶, compiled onto the real spiky SpikingNet (native CPU kernel) and exported live to a linked graph / animation / raster inspector. Just 6 input neurons, each forced to spike at a distinct first-spike time (earlier = larger) — no tap bank. The 3 detectors are made timing-sensitive by their own dynamics: leaky integrators whose membrane at a fixed readout tick reads the input spike times directly, forming the hyperplane comparators sign(W·x+b) that select 1 of 8 rows; outputs emit their value as spike latency. A tiny 25-neuron / 259-synapse network — click any neuron or synapse for its full NeuronMeta / weight / delay. Comparator bits match the exact oracle on ~76% of random real inputs (the leaky readout is nonlinear — the price of dropping the tap bank).

⑥ Evolved spiking net — discovered, not constructed

The opposite approach to ①–⑤. Instead of hand-compiling the circuit, a DB-backed neuroevolution search bred spiking nets against the same latency-coded LUT-ordering task — ~1.5M genomes evaluated over lineages ~4000 generations deep (mutation + crossover, persisted in MongoDB, CPU-only). This is the best net found (fitness 0.881): an arbitrary, un-designed topology — 6 inputs → 11 hidden → 4 outputs, 52 synapses — whose four output neurons' first-spike order reproduces the LUT oracle's row ranking. Same live inspector (graph / animation / raster); the shown input is one the evolved net orders exactly right. Click any neuron or synapse for its evolved NeuronMeta / weight / delay.

⑦ Evolved Izhikevich RS/FS net — the two canonical neuron types

A newer neuroevolution run constrained to the two canonical Izhikevich-2006 neuron types — RS excitatory and FS inhibitory — with only a per-neuron RS/FS bit evolved (no continuous neuron params). The best net (Kendall tau-b 0.796, sole fitness) is a compact 6 inputs → 6 hidden → 4 outputs, 37 synapses. This page renders its topology and runs the full quadratic Izhikevich simulation live in your browser (a faithful port), so you can watch spikes propagate and the four outputs’ first-spike order emerge and be scored against the oracle. Constraining neurons to RS/FS cost nothing vs the unconstrained model — evidence the search space was over-broad.

⑧ Evolved associative memory — a spiking net you can TEACH (Dale + STDP)

Unlike ①–⑦ (which compute a fixed function), this net was evolved to be TAUGHT: each episode it’s shown two brand-new arbitrary input→output-order mappings, stores them via spike-timing plasticity (STDP), and recalls each from its input alone. Random targets per episode make feedforward shortcuts impossible — only genuine storage scores. Obeys Dale’s law (excitatory/inhibitory is a neuron property), inhibition fixed & fast, only excitatory synapses learn. Mean storage-gain ~0.67, generalizes to unseen mappings. Learning-to-learn by evolution.

⑨ LUT smart-initialization — a clean 3-layer mapping, no scaffolding

Closes the loop from the hand-built exact construction (①) to the evolved substrate: a trained lookup table is compiled into a tiny spiking net by SEEDING from its hyperplanes (tau-b ≈ 0.53) and then running plain weight+delay evolution (no STDP, no store-recall) to evolve away the leak/threshold distortion. Drops ALL the scaffolding — no clock, no complement neurons, no row decoder — just latency-in → detectors → latency-out under Dale’s law. Recovers to tau-b ~0.78 (all outputs fire 100%, exact-order-match ~55%) while staying SMALL (it pruned below the seed). Interactive spike-playback per input.

⑩ Walker2d RL policy → spiking, LIVE — a trained controller in spikes

A real Walker2d SAC control policy (32 lookup tables over the 17-D observation) compiled into a latency-coded spiking network and run LIVE in your browser. Because the policy is 4-bit quantized, the spiking comparison Σ w·t < θ is exact integer arithmetic — the 32 tables' addresses resolve with zero weight error; the 6 action values come out as output-neuron spike TIMES. Pick an observation, watch the spikes flow input→address→action, and see the decoded actions match the lookup-table oracle. Runs client-side from a 59 KB embedded model, nothing precomputed. The ladder taken all the way to a working RL controller.

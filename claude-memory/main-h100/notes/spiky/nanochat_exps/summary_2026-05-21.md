# LUT-LM Experiments — 2026-05-21

**Reference:** exp453 (LION on LUT β=(0.9,0.95), lut_lr=2e-4, bs=16, 8000 steps, 89.4M, NAP=6 everywhere, full LayerNorm) = **1.4967 bpb** — the standing bs=16 LUT-LM best. All runs fork it (via exp454, which adds checkpoint saving) and change one thing.

Theme of the day: after the optimizer axis was found tapped out, we (1) confirmed the optimizer/lr choices, (2) tested several quality/convergence levers — most negative — and found one real-but-costly bpb win, and (3) fully characterized what the pre-LUT norm actually does.

---

## Headline outcomes

1. **exp453 (1.4967) remains the reference.** No cheap lever beat it meaningfully.
2. **Output-scatter specialization is a real bpb lever but costs lookups** — exp466 (qkv+out_proj as many narrow output-specialized tables) = **1.4937 (−0.0030)** at ~2× LUT lookups; set aside as too heavy for the matmul-free goal.
3. **The pre-LUT norm (ln_pre/ln_post) is purely per-token magnitude calibration** — the learnable affine is inert; any per-token scale (std/RMS/MAD/mean-abs) is equivalent. **mean-abs (`x/(mean(|x|)+eps)`, zero params, no sqrt/centering) is the cheapest drop-in** → adopt as the new baseline *recipe* (exp475 = 1.4962, = exp453 within noise, cheaper).
4. **The convergence bottleneck is gradient quality, not capacity/conditioning/decoder** — confirmed by GN dead-end, frozen-decoder, and LUT+Linear all being negative/neutral.

## 1. Optimizer / lr confirmations (exp454, exp467–469)
- **β₂ is a flat plateau:** exp454 (0.93) = 1.4969 ≈ exp453 (0.95) = 1.4967. The β₂ sweet spot spans [0.93, 0.95].
- **lut_lr=2e-4 is optimal:** LION lr sweep (1e-4/4e-4/8e-4) all monotonically worse than exp453's 2e-4 (1e-4 too small, 4e-4/8e-4 overshoot — the non-adaptive sign step makes lr load-bearing). 2e-4 (matched to AdamW's realized lr ~2.2e-4) confirmed. No free win.
- LION is **not adaptive**: step = ±lr per coord (sign only); only direction (β₁/β₂) and the global schedule vary. This is *why* lr matters more for LION than Adam.

## 2. Gauss-Newton optimizer — dead end (exp455)
Damped GN on LUT weights: `ΔW[t,r] = −lr·m/(count+λ)`, count = per-row visit count (= exact diagonal Hessian for the linear-in-weights LUT), exposed via new `enable_visit_count_stash` in tiny_multi_head_lut.py. Landed ~+0.013, **between SGD (+0.034) and LION/Adam** — "denoised SGD." Lesson: GN keeps gradient *magnitude*; the winners (sign/Adam) discard it. **The bottleneck is gradient NOISE, not conditioning** (count is the right curvature for a noiseless problem; the right statistic for a noisy one is variance/sign). Conditioning was never the limiter — Adam/sign already handle it.

## 3. Adding capacity — all negative (exp456–458, exp463)
- **Parallel "main-effect" branches** (NAP=1 tables, exp456; VectorToDominance→Linear, exp457/458): zero-init dominance branch = +0.027 drag; the base NAP=6 LUT already encodes pairwise dominance, so a first-order term is redundant.
- **LUT(x) + Linear(x)** (exp463): only ~−0.001 even with a full dense matmul bolted on → **the LUT body is NOT linearly deficient** (good negative; confirms matmul-free thesis — the gap to vanilla isn't "LUTs can't do linear maps").

## 4. Frozen decoder — convergence is the limit (exp459)
Froze the unembedder at a converged value (loaded from exp454; verified all 96 anchor buffers byte-identical, so the body could in principle reproduce the teacher's representation). Result **1.5138 (+0.017)**: huge early lead (−0.215 @ step 200) but the body still converges to a slightly *worse* floor than full co-training. → the gap to vanilla lives in the **LUT body's convergence (gradient quality)**, not the decoder. Co-adapting the decoder even slightly helps.

## 5. Output-scatter specialization — real bpb win, costly (exp460–466)
`sparse_scatter`: each table writes `n_out/f` outputs scattered into the full output → each output dim assembled from ~tph/f tables. At fixed output dim:
- 4× sparse alone (exp462): out_proj 25.2M→6.3M for +0.015.
- **4× sparse + 4× tph (param-matched): beats exp453.** out_proj (exp464) −0.0024; qkv (exp465) −0.0016; **both (exp466) −0.0030 = 1.4937** (sub-additive ~75%). Many narrow output-specialized tables > fewer wide tables at equal params.
- **Cost: 4× more lookups/token** on the restructured modules (read-bandwidth). Set aside — too heavy for the matmul-free goal; exp453 preferred.
- exp460 (all-LUT 4×) was confounded: v_lut (16→4) over-sparsified.

## 6. Pre-LUT norm fully characterized (exp470–475) — the clean result
The 2×2 (L1/L2 × center/no-center), all ≈ exp453 within noise:

| | center | no center |
|---|---|---|
| **L2** | exp472 std → = exp453 exact | exp474 RMS → ≈ exp453 |
| **L1** | exp473 MAD → ≈ exp453 | exp475 mean-abs → 1.4962 |

Plus ablations: exp470 (scalar γ, no divisor) +0.05; exp471 (per-channel γ, no divisor) +0.07.

**Conclusion:**
1. The pre-LUT norm does exactly one load-bearing thing: **per-token magnitude calibration** — keep `|d| ~ soft temperature T` so the soft-backward softmax is appropriately sharp (not uniform/mushy, not saturated). Without the divisor, raw tok_emb is tiny (`|d|~0.05 ≪ T=0.5`) → diffuse gradient → +0.05–0.07 deficit.
2. The **learnable affine (γ, β) is inert** (exp472 = exp453 exactly with γ,β frozen at init). The LUT weights don't participate in selection and their output magnitude is normed away downstream → per-channel γ/β add nothing.
3. **Any per-token positive scale works** — std, RMS (≈std·√(1+(μ/σ)²)), MAD, mean-abs. For the LUT, μ cancels in differences and the scale constant is absorbed by the learnable T.
4. **mean-abs (`x/(mean(|x|)+eps)`) is the cheapest correct choice** — no params, no centering, no square, no sqrt → most matmul-free-friendly. **Adopt as the new baseline recipe** (exp475 = 1.4962, = exp453 within noise, simpler/cheaper norm). q_norm/k_norm/ln_final stay full LayerNorm (they feed SDPA/unembedder, where std/affine do real work).

Note: WD on LUT weights was NOT swept — analysis showed it's redundant (LUT output normed away downstream → WD acts only as effective-LR, which `lut_lr` already tunes).

## 7. Entry↔output alignment probe (analysis_entry_output_corr/)
Faithful decomposition of `output = Σ selected entries`. exp365 (tiny, out_proj tph=128) deep out_proj **collapses to a redundant rank-1-ish code** (L5 cos(entry,output)=0.999); exp454 (out_proj tph=1024) stays **distributed** (cos≈0.15). Collapse is a *selection* phenomenon at low tph (stored rows stay near-orthogonal). Higher tph → distributed code → mechanistically why out_proj benefits from more tables (cf. exp390, exp464).

## Today's mechanistic findings (2026-06-11)

### Compute precision is NOT the regularizer at FastMHL scale
exp747 (fp32 LUT storage + explicit bf16 compute cast on the embedding_bag gather) tracks closer to exp732 (1.3912) than exp737 v2 (1.3872). So the ~4 mb gain of exp737 v2 came from **bf16 LUT *storage* interaction** (bf16 .grad accumulation under grad_accum=2 acting as regularizer), not from bf16 gather precision.

### bf16 head/SDPA at training is fundamentally incompatible with sparse-LUT Lion
`diag_drift_mechanism.py` showed per-step grad cos collapses from 0.999995 → 0.03 in 100 steps under bf16 head. Chaotic divergence from Lion sign-step amplifying tiny bf16 noise at sparse LUT rows. Confirmed across exp741/742/743/744/745/748/749/753 — every flavor of bf16-head-during-training drifts.

### bf16 quantization at INFERENCE is free
`eval_exp738_bf16_except_head.py` and `eval_exp750_bf16_head.py` verified: cast all weights to bf16 at save time, val_bpb changes by < 0.5 mb (eval noise). No optimizer step at inference → no chaotic compounding.

### Global grad clip(1.0) is the new free win
exp750: exp737 v2 + `clip_grad_norm_(model.parameters(), 1.0)` → −0.9 mb at 4K. exp749 (clip + bf16 head) shows clip recovers ~5 mb of bf16-head drift but can't fully fix it.

### Deployment bandwidth comparison (full bf16 quant)
| | exp750 LUT-LM | exp738 vanilla |
|---|---|---|
| backbone HBM/token | 7.3 MB | 21.2 MB (LUT 0.34×) |
| head HBM/token | 25.2 MB | 25.2 MB (identical) |
| total / token | 32.5 MB | 35.8 MB (LUT 0.91×) |
| val_bpb (full bf16) | 1.3861 | 1.3982 (LUT −12.1 mb) |

## Final SOTA recipe (committed as `fast_multi_head_lut.py` default)

```python
# LUT modules
FastMultiHeadLUT(
    weight_dtype=torch.bfloat16,       # bf16 storage (HBM bandwidth -50%)
    use_bf16=True,                     # bf16 compute (autocast + body cast)
    forward_mode="hard",
    backward_mode="dense_K",
)
# use_bmm_wgrad is unconditionally True in the body

# Optimizer
class Lion(torch.optim.Optimizer):
    # fp32 master in state["master"] when param.dtype != fp32
    ...
adam = AdamW(non_lut_params, lr=3e-4, wd=0.1)
lion = Lion(lut_params, lr=2e-4, betas=(0.9, 0.95))

# Train loop
for step in ...:
    loss.backward()
    clip_grad_norm_(model.parameters(), 1.0)     # <-- the clip lever
    for opt in [adam, lion]: opt.step()

# Head
self.unembedder = nn.Linear(D, VOCAB_SIZE, bias=False)  # fp32 during training
# Train forward: head and SDPA stay fp32 (avoid chaotic divergence)

# At save time
for p in model.parameters():
    p.data = p.data.to(torch.bfloat16)            # bf16 deployment is free
```

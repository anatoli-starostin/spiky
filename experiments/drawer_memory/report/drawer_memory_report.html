Drawer memory: live experiment report

LUT-addressed memory written at inference time as a replacement for attention. Generated 2026-10-20 12:07 from 105 finished runs; abstract last revised 2026-10-20 12:10.

Abstract

Drawer memory — a hash-addressed associative memory written at inference, using spiky's LUT addressing (anchor-pair sign bits → table cells) — replaces softmax attention: each token stores its value in a few table cells chosen by fixed yes/no comparisons, and later tokens read the cells their own comparisons select. On associative recall it is close to linear attention up to 64 pairs (within 0–1.6 points) and beats it at equal parameters; on real text (enwik8) hard drawers are 2.5% behind linear attention at 5.4× lower cost per token (measured, CPU), and a bounded soft read (each token reads and writes its 4 most likely cells per table instead of one) halves that gap (to 1.4–1.6%) at 2.2–2.7× lower cost; against softmax with a KV cache the saving is ~115× at 16k context. Two design rules make it work: one shared address projection, and many small (4-bit) tables; soft-to-hard training largely fixes slow learning. Open: behaviour at real scale and with a fused kernel, which need a GPU.

Key findings — current state of knowledge

Drawer memory stores each token's information in a few cells of fixed-size tables, chosen by yes/no comparisons of the token's own numbers (spiky's LUT addressing); later tokens read the cells their own comparisons point to. Mathematically it is linear attention with a sparse, binary feature map; per token it touches a fixed number of rows.

Recall (synthetic MQAR)

  • It works. 99.8–100% recall at 16–32 key–value pairs, comparable to linear attention of the same memory size (99.97–99.99%).
  • 64 pairs. Drawers 16×4 (memory 256) start learning at step ~1,250, earlier than linear attention (~2,250), and reach 98.3% / 99.1% vs 99.9%. With memory 64, 10,000 steps give 95.4% (hard) and 97.1% (neighbour cell) vs 99.9%.
  • Equal parameters. Linear attention with ~the same parameter count (F=32) reaches 96.9% / 97.4% at 32 pairs vs 99.8% for drawers, at the same measured speed. On text this advantage does not hold (Shakespeare: 2.225 vs 2.238 bpc).
  • Non-adjacent pairs (2 filler tokens). Plain drawers learn late (step ~2,250) and reach 90–91% vs 99.99% for linear attention; softmax fails in this setting with or without RoPE (3.4–4.3%). Soft-to-hard addressing lifts drawers to 96.3–99.8% at no inference cost.
  • Memory editing (8 of 16 keys re-assigned). Plain additive writes: 98.0–98.2% on updated keys, the same as linear attention (98.0%; softmax 99.99%). Decay writes are worse (93.8–96.5%); overwrite-style writes do not learn (4.2%) because every token overwrites shared cells.

Design rules

  • One shared address projection. With separate query/key projections learning never starts (0.4%).
  • Many small tables. 4 bits (16 cells) per table is the sweet spot: 6-bit tables learn late or not at all and depend on the anchor draw; 2-bit tables hit a collision ceiling (77–79% at 32 pairs, 27.7% at 64 pairs with memory 64).
  • Failures were learning speed, not capacity. A run at 0.45% after 3,000 steps reached 100% with 10,000.
  • Soft-to-hard addressing. Soft cell addresses that harden by 30% of training largely fix slow learning; the final model is fully hard. A higher learning rate is not an alternative: drawers have a narrower learning-rate window than linear attention.
  • Spiky's read tricks. The neighbour cell helps 6-bit tables, depending on the anchor draw (99.8–99.9% with one, 25.8% with another); the confidence score hurts.
  • What did not help. Hybrids with a local softmax window (two designs), squared match-count reads, decay or overwrite writes.

Why learning 'clicks' (diagnostics)

  • Address agreement. In layer 1 the share of tables where a query lands in the cell that stored its value jumps from 19% to 81% between steps 750 and 1,000, exactly when recall jumps; it ends at 93%. Hashing quality is good throughout (entropy 0.96–0.99 of maximum, balanced bits, collisions at chance).
  • Failed 6-bit runs. Agreement crawls from 2% to 11%; the optimiser correlates the bits (|corr| 0.09 → 0.31), coarsening addresses and quadrupling collisions without reaching agreement.
  • Noisy reads. The correct value carries only ~11% of a read's weight; later layers still decode it.

Measured cost (CPU, PyTorch, no custom kernel)

  • Per token, equal memory (256). Drawers 16×4: 5.2–5.7 µs; linear attention: 27–29.5 µs (~5×), flat in context length. Softmax with a KV cache: 20 µs at 256 tokens, 635 µs at 16k (~115× drawers), with 16 MB of state per sequence instead of 132 KB. The calculated 60× arithmetic saving shrinks to ~5× because projections and gather/scatter do not get cheaper with sparsity. Timings vary ±5% between runs.
  • Accuracy vs cost (32 pairs). Linear: 96.9–97.4% at 5.2 µs (F=32), 99.5% at 7.8, 99.94% at 13.7, 99.98% at 28.2. Drawers: 96.9% at 2.9 µs (F=64), 99.4% at 4.0, 99.8% at 5.4. Up to ~8 µs drawers are more accurate; above 99.9% only linear attention gets there, at 2.5–5× the cost.

Real text

  • enwik8 (clean test, no overfitting). After 1,500 steps: linear attention 2.341 bpc, hard drawers 2.400 (+2.5%, 5.5 µs vs 29.5), drawers with a bounded soft read 2.372–2.379 (+1.4–1.6%, 10.9–13.2 µs). The bounded soft read stores and reads the 4 most likely cells per table (exact top-4, or the cheaper flip-2 choice); a longer soft phase alone does not close the gap.
  • Tiny Shakespeare. Drawers 2.237–2.239 bpc, between linear attention (2.217) and softmax (2.247–2.251), but all models overfit (~25 passes; training 1.6–1.8 bpc), so this ranking mixes modelling power with regularisation. A local-window-only model reaches 2.47 bpc: drawers' long-range memory is worth ~0.23 bpc.
  • Scale. A 4× larger model memorises Tiny Shakespeare (training 0.69 vs held-out 3.33 bpc); a scale test needs a large corpus and a GPU.

Target claim (from external review): comparable recall with fewer memory accesses and lower measured decoding cost. Status: met at small scale on recall; on real text drawers are 1.4–2.5% behind linear attention at 2.2–5.4× lower measured cost. Open: real scale and a fused kernel (GPU).

Decode speed benchmark

Question. Measured, not calculated: how long does one attention-replacement layer take per new token, as the context grows from 256 to 16,384 tokens? CPU, PyTorch, recurrent (step-by-step) form; the drawer step was checked to reproduce the training-time output to 1e-6.

What we learned. Measured, at 64 sequences per batch (throughput): drawers 16×4 cost 5.2–5.7 µs per token and 4×6 cost 3.0 µs (but 4×6 learns unreliably), against 27–29.5 µs for linear attention with the same state (F=256): 5× and 9× faster at equal memory, flat in context length. Against linear attention with ~equal parameters (F=32, 8× smaller state) drawers 16×4 are equally fast. Softmax with a KV cache costs 20 µs per token at 256 tokens and 635 µs at 16,384 (115× drawers 16×4), with 16 MB of state per sequence instead of 132 KB. At batch 1 framework overhead dominates: drawers 40–44 µs, linear F=256 87 µs, linear F=32 37 µs. The analytic estimate was ~60× less arithmetic than linear F=256; the measured gain is 5–9×, because projections and gather/scatter overhead do not shrink with sparsity (PyTorch CPU, no custom kernel). Memory-size sweep (context 1,024): linear F=32/64/128/256 cost 5.2/7.8/13.7/28.2 µs per token; drawers with 4-bit tables cost 2.9 (F=64), 4.0 (F=128), 5.4 (F=256): the gap grows with memory size because drawers touch a fixed number of rows. Bounded soft reads as implemented (score every cell of a table, then take the top 4): 16 × 4 top-4 costs 31.1 µs per token, more than linear attention (28.3); 4 × 6 top-4 costs 13.0 µs, 2.2× cheaper than linear F=256 but 2.3× the hard design (5.7). Choosing the 4 cells directly from the 2 least-certain bits (flip-2) brings this down only to 10.9 µs: most of the extra cost is the weighted reads and writes of 4 rows per table and PyTorch's per-operation overhead, which a fused kernel should reduce. Cheap flip-2 soft read (4 × 6 bits): 10.9 µs per token (exact top-4: 13.2; hard 16 × 4: 5.5; linear F=256: 29.5). Timings vary by about ±5% between benchmark runs.

Batch 5 — proofs of concept: real text, gaps, 64 pairs

17 of 17 runs finished · 2026-10-19, finished 20:33

Question. Does drawer memory work on real text (character-level Shakespeare)? Does recall survive filler tokens between key and value, and 64 pairs with small tables? Anchors are drawn per seed from here on.

What we learned. On Tiny Shakespeare (two seeds) drawers 16×4 reach 2.237–2.239 bpc, between linear attention (2.217) and softmax (2.247–2.251); seed spread ≤0.004, so the ordering is real. Neighbour cell: 2.246 / 2.253, a faster start but a slightly worse end, so it does not help on text with 4-bit tables. Drawers improve from the first evaluation, without the delayed 'click' seen on recall. All models see only local order through the 4-character token shift, which handicaps softmax relative to normal practice. Recall with 2 filler tokens between key and value (two seeds): linear attention 99.99–99.997%, drawers 16×4 90.0% / 91.2%; drawers start learning only at step ~2,250 (no gap: ~1,000), so the gap mainly slows the store/read agreement down. Softmax attention (no positional encoding, seed 0) did not learn the gapped task within 3,000 steps (4.3%), so drawers beat softmax but trail linear attention here. 64 pairs, memory 256 (two seeds): drawers 16×4 learn from step ~1,250 (linear attention ~2,250) and reach 98.3% / 99.1% vs 99.9%. At the other extreme, 16 tables × 2 bits (4 cells each, memory 64) at 64 pairs starts learning early (step ~1,500) but plateaus at 27.7%: with 4 cells per table every cell holds ~16 of the 64 pairs, a hard collision ceiling. The bits-per-table trade-off has two sides: too many bits slow learning, too few cap capacity; 4 bits was the sweet spot at both 32 and 64 pairs. Caveat found later: the runs make ~25 passes over Tiny Shakespeare and all models overfit (final training bpc: softmax 1.75, linear 1.79, drawers 1.83, half-width hybrid 1.64 vs validation 2.22–2.30). Drawers overfit least, which helps their validation score.

Batch 6 — diagnostics, memory editing, hybrids

24 of 24 runs finished · 2026-10-19 evening – 2026-10-20 01:49

Question. Why does learning click when it does (address-match rate)? Can the memory replace old values? Does a local attention window plus drawers beat either alone? How does accuracy trade against cells touched?

What we learned. Address diagnostics (16 tables × 4 bits, 32 pairs): the recall click coincides with a jump of layer-1 store/read address agreement from 19% to 81% of tables between steps 750 and 1,000 (final 93%). Hashing quality is good from the start (entropy ≥0.93 of maximum, bit bias ≤0.1, unrelated-pair collisions ≈ 1/16 = chance), so learning is limited by agreement, not by address quality. Layer 2's addresses are collapsed into ~13% of cells before the click (entropy 0.09) and spread out afterwards; layer 2 does not do key matching (agreement 40%). The correct value's share of the layer-1 read is ~11% (own write and the key token's write share the same cells). Failed run (4 tables × 6 bits, same task, 0.44% recall): layer-1 agreement crawls from 2% to 11% over 3,000 steps and only 32% of queries match their value in at least one table. The bits become correlated (mean |corr| 0.09 → 0.31) and entropy falls from 0.97 to 0.80: the optimiser is effectively merging bits (fewer distinct cells) to raise agreement, which quadruples unrelated-pair collisions (0.067 vs chance 0.016) without crossing the threshold. This is the mechanism behind 'fewer bits per table learn faster'. With the neighbour cell (4 × 6 bits, anchors drawn for this seed) agreement crawls the same way to 11% at step 2,000, then crosses: 46% at 2,500, 56% at 3,000 (recall 25.8% and rising when training ended). After the crossing the bits de-correlate again (|corr| 0.18 → 0.07) and collisions fall back to chance. With the original anchors the same variant had reached 99.8–99.9%: 6-bit tables are sensitive to the anchor draw, 4-bit tables have not been. Parameter-matched baseline: linear attention with F=32 (559,616 parameters, vs 526,850 for drawers) reaches 96.9% / 97.4% at 32 pairs (two seeds), below drawers 16×4 (99.8%) at the same measured decode cost (5.5 vs 5.2 µs per token). Glossary

Drawer memory — this project's name for a hash-addressed associative memory written at inference; in the plain-language analogy, tables are cabinets and cells are drawers.

MQAR — multi-query associative recall: a sequence of random key→value pairs, then the keys again; the model must name each key's value. Recall — share of those answers that are correct (chance 0.4%). Memory F — memory size per head: cells (drawers) for drawer memory, feature dimension for linear attention; equal F means equal recurrent state. Tables × bits — number of tables (cabinets) and yes/no questions per table; cells per table = 2^bits. Neighbour cell — also read the cell one answer away from the least certain question. Confidence — down-weight tables whose answers were close calls. Step reaching 50% — training step at which recall first exceeded 50%, our measure of when learning 'clicks'. bpc — bits per character on held-out text, lower is better.

Soft-to-hard addressing — training trick: cells are chosen softly (a weighted mix over all cells of a table) at the start and harden gradually; after 30% of training the model is fully hard, the cheap form used at inference. Bounded soft read — inference-time variant: each token writes to and reads from its 4 most likely cells per table, weighted by their probability (exact top-4, or the cheaper 'flip-2': the cell plus those reached by flipping the 2 least-certain bits). Hybrid — a model mixing a local softmax window (last 16 tokens) with drawer memory. enwik8 — the first 100 MB of English Wikipedia, a standard byte-level language-modelling benchmark; 90 MB for training, 5 MB held out. µs per token — measured time for one attention-replacement layer to process one new token during generation (CPU, PyTorch, 64 sequences at a time).

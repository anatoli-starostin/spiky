Drawer memory: how it reads, writes and learns

A replacement for attention: every token files its information into drawers picked by its own yes/no answers, and later tokens open the drawer that matches what they are looking for.

The puzzle

The model reads pairs “key → value”, then gets asked for some keys. It must answer with the value that was stored with that key. Here: A→1, B→7, C→3, then “B?” and “A?”.

The 4 things to remember

  1. Drawers start empty for every new text. They are a scratchpad for this text only, not stored knowledge.
  2. Address = answers to yes/no questions (“is number #2 bigger than number #7?”). 3 answers → a number 0…7 → one drawer.
  3. Writing and reading use the same translator (“shared projection”), so the same key always lands in the same drawer.
  4. Several tables, each with different questions, vote together. If two keys collide in one table, the other tables break the tie.

Simplified for the picture: 2 tables × 8 drawers. The real run used 4 tables × 64 drawers per head, 4 heads, 2 layers.

The training loop (repeated 3,000 times)

1New random puzzle

64 random texts like “A 1 B 7 … B? A?”, 16 pairs each.

2Run inference

Exactly the process from tab 1: write, then read, answer.

3Check answers

Compare with the right values. How wrong were we?

4Nudge

Slightly adjust the translator and value maker so next time it is a bit less wrong.

The drawers themselves are never “trained”: they are thrown away after each text. Training only teaches the model how to file and how to search.

The hard part: a drawer number has no “almost”

To learn, the model needs a hint like “you were close — go a bit this way”. But a drawer is either the right one or not; there is no “almost right drawer”. The trick (borrowed from spiky): forward we use the hard drawer, but when computing the hint we pretend the choice was soft — a probability spread over drawers. Close-call questions spread the probability; clear-cut ones concentrate it.

Why shared vs separate translator decides everything

Separate (failed: 0.5%)

Filing “B”: writer translator → drawers 3 / 6.
Asking “B?”: reader translator → drawers 1 / 4.

Different drawers → finds nothing useful. At the start the two translators are random and never agree, so the learning hint is almost zero: the model never discovers that they should agree.

Shared (worked: 99.9%)

Filing “B” and asking “B?” both go through the same translator → drawers 3 / 6 both times.

The match is automatic from step one. The model only has to learn what to file — and after ~1,300 steps it “clicks”.

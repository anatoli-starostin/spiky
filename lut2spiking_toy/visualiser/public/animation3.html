Aggregating LUTs — delay-coded tables + a listening aggregator

Contents · Single table · Charge summation · Aggregator population

A different way to add two tables. Each table stays a self-contained model-1 black box: it selects a row and emits its output vector as latency-coded spikes (value in the conduction delay, like the single-table page) — it doesn't know it's being summed. A separate population of aggregator neurons then listens to every table's output spikes and produces the sum, re-emitted as latency spikes. Contrast with the charge-summation model, where the tables deposit charge on shared outputs.

One network — inputs → two delay-output tables → a listening aggregator → summed output spikes

Left→right: ONE shared input population fans out to Table 1 and Table 2; each does its detector → complement → row-select and drives its OWN TAB-OUT neurons, which emit latency spikes. The aggregator neurons (Σj) listen to output j of both tables, integrate, and fire the summed spike.

How the middle layers are wired — DETECT · COMPL · ROWS · TAB-OUT · AGGREGATOR
  • DETECT (Hk) — hyperplane sign-test; after the CLOCK it fires iff ⟨Wk,x⟩+bk ≥ 0 → address bit k. Incoming = weighted input→detector synapses (−/+).
  • COMPL (Ck) = NOT Hk: CLOCK excites Ck, Hk sends an inhibitory synapse (┄ dashed), so Ck fires iff Hk did not.
  • ROWS (2K one-hot) — K-way coincidence AND; exactly the row matching the bits fires.
  • TAB-OUT (oj) — each table's OWN output neurons; the winning row drives output j through a conduction delay = α+β·Ot[rt][j], so oj fires at a latency encoding the value (bigger = later).
  • AGGREGATOR (Σj) — one per output dim; listens to output j of both tables (purple listening edges) and sums them (see below).

The aggregator — a sustained current that turns spike times into a sum

A plain integrate-to-threshold aggregator would fire on the k-th arrival — an order statistic of the arrival times, not their sum. The trick: each incoming table-output spike switches on a sustained constant current I from its arrival until a fixed readout clock T_agg. The membrane then holds the sum of elapsed times:

Vj(T_agg) = I·Σt(T_agg − tt,j) = I·(N·T_agg − Σt tt,j)
with tt,j = GZt + α + β·Ot[rt][j]  ⇒  Σt tt,j = C₀ + β·Sj,   Sj = Σt Ot[rt][j]
⇒ Vj(T_agg) = const − I·β·Sj  (affine in the true sum) ⇒ re-emit at  t_outj = T_agg + A + B·Sj

Constants (this page): per-table code α=5, β=1, ground zero GZt = row-fire + 0.6; aggregator I=1, readout T_agg = last table spike + 0.6, emission A=T_agg+5, B=1 (same bigger=later latency convention, so the summed spikes are themselves composable). Two ground zeros: per-table GZt and the aggregator clock T_agg.

Ground truth vs aggregator — live check for THIS input

The two tables never shared an output. Per dim j: the direct LUT sum O₁[r₁][j]+O₂[r₂][j], the value read from the aggregator membrane Vj, and the value decoded from the emitted summed spike time (t_out−A)/B. All three must agree.

Verified

Over 50,000 random inputs (analysis/aggregator_check.py): the aggregator membrane readout equals the true Σt Ot[rt][j] to 1.8e-15, and the emitted summed-spike times decode back to the sum to 4.6e-15 — 100% match. A naive integrate-to-threshold aggregator (order statistic) is off by up to 3.44 — it fires on an arrival order, not the sum. Sustained-current-until-T_agg is what makes spike times add.
